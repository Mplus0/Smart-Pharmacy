# 识别 MD5 与 Excel 记录

本功能在现有节点中运行，不增加 ROS 节点、话题或网络传输。

## 记录时机与内容

- 板一执行任务：`F1_yaofang_v5.py` 的 `apply_board1_selected_msg` 接受本轮任务时，记录解析后的取样窗口、样本数量和送样窗口。仅记录选中的任务；复用 `board1_received` 避免同次识别重复记录，也覆盖已有对车任务选择入口。
- 板一干扰码：`F1_detect_code_v5.py` 的 `announce_stable_board1_error` 通过原有连续稳定判定后，逐项记录归一化后的非空非法内容。复用原有每次访问一次的异常提醒分支；无有效任务但有稳定干扰码时也记录。不记录未选中的正常任务。
- 板二：`detect_board2_result` 接受结果时记录状态与等待秒数；忙碌秒数采用原有上下限修正后的实际任务值，空闲为 0 秒。当前结果来自键盘 TCP 服务端，记录其被主任务接受后的实际值。

输入不是二维码原始字符串，而是上述解析字段的 JSON：键排序、无额外空格、保留 Unicode。统一调用 `hashlib.md5(content.encode('utf-8')).hexdigest()`。
Excel 的“具体内容”保存同一份 JSON 文本；干扰内容中的控制字符由 JSON 转义，避免写入 Excel 时丢失或改变 MD5 输入。

## 保存与结束

- 保存目录：`pharmacy_pkg/result_md5/`，由记录模块所在包的位置确定，不依赖终端当前目录；不存在时自动创建。
- 固定文件名：`recognition.xlsx`，每次运行结束直接覆盖上次结果，不添加时间戳或随机后缀。
- 列顺序：序号、识别板、内容类型、具体内容、MD5。
- 完成 `max_rounds` 规定轮数并返回起点后，先导出再执行原有退出流程。现有 shutdown 回调也会导出，成功后不重复生成。
- `max_rounds=0` 为持续模式，退出主任务时导出；本次未增加比赛时间或样本数终止条件。
- 两个已有进程通过结果目录内的 `car车号.sqlite3` 共享记录。每次主任务启动清空该车旧记录，导出仅包含本次运行，不维护历史运行时间。不要同时启动多个任务实例写入同一结果文件。
- 记录或导出失败会写 ROS 错误日志；数据库中的已写入记录保留。强制杀进程或断电不会执行 shutdown，不能保证自动生成 Excel。

## 必要依赖与验证范围

沿用现有 Python 环境。`hashlib`、`sqlite3` 均为 Python 标准库；运行主任务的 Python 需要安装兼容版本的 `openpyxl`。Ubuntu 18.04 / Python 2.7 环境使用对应发行版的 `python-openpyxl` 包，已在 `package.xml` 声明运行依赖。不要给 Python 2.7 安装仅支持 Python 3 的新版 openpyxl。

主任务在连接导航服务之前加载 openpyxl，缺失依赖会直接报错，避免运行完整任务后才发现缺少导出库。

开发阶段仅进行静态审查，没有运行程序、测试脚本或生成 Excel。部署后需验证：正常轮次结束导出、连续模式退出导出、干扰码与选中任务记录、板二空闲/忙碌记录，以及再次运行后覆盖 Excel 且不混入上次记录。
