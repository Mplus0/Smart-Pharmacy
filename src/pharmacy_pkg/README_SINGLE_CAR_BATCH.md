# 单车整板连续配送

## 手动放行

原启动命令及视觉/主任务的启动延迟不变。主任务完成初始化、连接 move_base 和清图服务后，提供 `std_srvs/Trigger` 类型的 `/nav_pharmacy/start` 服务，并保持待命。此时可以展示节点图、检查定位，不会发送配送导航目标。

在同一 ROS Master 的另一个终端执行以下命令后，开始自动运动：

```bash
source ~/.bashrc
rosservice call /nav_pharmacy/start "{}"
```

首次请求返回 `success: True`；重复请求返回 `success: False` 和 `Task already started`，不会重置或重复启动任务。启动服务不是暂停/恢复接口；整个主任务进程只需确认一次，后续任务和批次自动继续。初始化未完成时服务尚不可用，初始化失败时也不会提供服务。待命时可用 Ctrl+C 正常退出。

服务位于已有主任务节点内，不增加独立节点；双车若使用同一主任务脚本，每辆车也需要各自放行，原轮流令牌仍有效。本次未运行服务调用或实车测试。

## 整板任务流程

单车模式（`enable_dual_car=false`）在板一完成原有稳定识别后，缓存本次整板的全部合法任务。沿用原优先级：样本数从多到少，相同数量按窗口编号从小到大。同样内容出现在不同格时仍是不同送样任务。空白和非法内容不加入队列，异常语音逻辑不变。

例如四格依次为 `AB / ABC / C / AC`，执行顺序是：窗口2的ABC、窗口1的AB、窗口4的AC、窗口3的C。原始格编号保持不变。

每项流程为：按 C→A→B 取齐该项样本 → 取样播报完成 → 板二结果及播报/等待 → 对应数字窗口停留并完成送样播报。

- 还有剩余任务：直接从当前送样窗口前往下一项所需取样窗口，不经过起点或板一。
- 本批任务全部完成：返回起点，累计完成一轮；未达到轮数限制时再去板一识别下一批。
- `max_rounds=1` 表示完成一整板任务并返回起点后退出、导出 Excel；`0` 为持续批次。
- 导航失败、识别超时等仍沿用原停止机制，不会因此继续弹出下一项。
- 每项被加载执行时重置取样完成标志、发布对应 CV2 并记录该项 MD5；缓存建立时不提前记录未执行的正常任务。板二每项重新查询。
- 不增加二维码刷新判断或跨进程重启恢复，内存队列随主任务退出而结束。

`/cam_return` 仍为 `Int32MultiArray`，首六项保留原选中任务格式；其后每六项表示一个按优先级排列的剩余任务：`[需要C, 需要A, 需要B, 样本数, 原始窗口索引, 异常窗口编号]`。一个消息完整携带本批任务，避免分别接收选中任务和整板结果造成时序问题。部署时应同步更新 `board1_selection.py`、`F1_detect_code_v5.py` 和 `F1_yaofang_v5.py`。

双车模式仍只使用消息首项，保持已有任务共享和轮流调度逻辑；本次未实现双车整板队列协同。

本次仅静态审查，未运行程序或测试。实车需验证多任务优先级、同内容不同窗口、非法格排除、各项播报完成后再移动、批次内跳过起点和板一，以及整批完成后返航退出。
